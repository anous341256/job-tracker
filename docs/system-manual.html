1. 系统概述

Job Tracker 是一个单用户空间隔离的求职行动管理系统。它不是招聘平台，也不替用户投递或回复邮件；其职责是把求职过程中的信息、行动和时间安排变成可追踪、可审核的数据。

项目说明
目标用户个人求职者；支持多个互相隔离的注册账户。
核心理念公司优先、行动优先。用户通常在收到新邮件、临近截止日期或出现新日程时使用系统。
主工作区行动中心首页：每家公司一张一级卡片，内部展示职位阶段、近期日程与未完成 To Do。
语言与时区界面以简体中文为主；系统默认 Asia/Tokyo，用户可在个人资料中修改时区。
数据边界业务数据保存在 MySQL；附件使用 Django Storage；Outlook 仅同步只读副本。
设计约束：AI 只能生成建议。任何日程、面试或 To Do 都必须经用户确认后才写入正式业务数据。

4.2 核心实体与约束

实体作用关键约束
Company行动中心一级容器同一用户下名称唯一；可归档；pinned_order 支持置顶排序。
JobPosition公司下的职位与招聘信息职位招聘状态与个人求职状态分离；薪资下限不得大于上限。
Application一次求职尝试同用户、同职位同一时刻仅允许一条非终止投递；结束后可再次申请。
ApplicationStatusLog投递状态时间线每次状态变更记录原状态、新状态、时间、说明与操作者。
CalendarEvent / Interview正式时间事项日程必须关联公司；已关联职位的面试使用 Interview，其他事项使用 CalendarEvent。
TodoItem可执行行动必须关联公司；可选关联职位、投递、来源邮件和操作链接。
SyncedEmail邮箱本地只读副本按“邮箱账户 + 提供方邮件 ID”去重；正文最多保存 50,000 字符。
AI 候选邮件日程 / To Do 建议版本化保存；批准或拒绝后保留记录；重复审批不重复创建正式对象。

4.3 数据保留与删除

  • 有关联公司、职位、投递或日程的数据优先归档或保护删除，避免破坏历史。
  • 未关联同步邮件最多保留 180 天，且每个邮箱最多保留最新 1,000 封；已关联邮件长期保留。
  • 手动删除邮件会写入仅含邮件 ID 哈希的忽略标记，45 天内不会因再次同步而重新导入。
  • 删除本地邮件副本时，正式 To Do 和日程保留；其来源邮件关联置空。

6. 安全与隐私

已实施控制

  • 业务查询按当前登录用户过滤；对象访问使用用户所有权校验。
  • 修改接口使用 POST、CSRF 防护；HTMX 请求同样经过 Django 认证和 CSRF。
  • 私有简历、文档下载前校验所有权；数据库仅保存文件路径和元数据，不保存二进制。
  • OpenAI API Key 使用独立 Fernet 密钥加密保存；页面只显示末四位，不写入日志。
  • 云端简历匹配前去除明显邮箱和电话号码，并要求用户主动开启敏感数据授权。
  • Host Agent 使用 Bearer Token 认证；Docker 只读挂载令牌文件，不暴露 Outlook 或 Ollama 新端口。

使用边界

  • JD 与邮件正文都被视为不可信输入；AI 无浏览器、数据库、邮件发送或系统工具权限。
  • Ollama 仅监听本机 127.0.0.1:11434；容器通过 Host Agent 间接调用。
  • 当前 Outlook 同步为经典桌面 Outlook 的只读模式，依赖 Windows 用户会话与 Outlook 登录状态。
  • 生产部署必须关闭 DEBUG、设置强随机 SECRET_KEY、启用 HTTPS 和安全 Cookie。
生产风险提示：当前 Docker 配置面向本地开发。若部署到公网，不能直接公开 MySQL、Redis、Docker daemon 或 Host Agent 接口；应使用反向代理仅暴露 HTTPS，并把密钥放在受保护的环境变量或密钥管理服务中。

7. 部署与运行

7.1 本机开发模式

项目虚拟环境、MySQL、Ollama 和运行状态均应保存在项目目录 D:\New project 下。PowerShell 执行策略受限时，使用单次 Bypass，而不要修改系统全局策略。

powershell -ExecutionPolicy Bypass -File "D:\New project\scripts\start-all.ps1"

7.2 Docker 开发模式

cd "D:\New project"
Copy-Item .env.docker.example .env.docker
powershell -ExecutionPolicy Bypass -File .\scripts\docker-up.ps1
服务作用默认端口 / 持久化
webDjango Web8000；媒体与静态文件 Volume
mysql业务主数据库主机 3307 → 容器 3306；MySQL Volume
redisDocker 任务队列 / 结果后端6379；Redis Volume
worker / beat异步任务与定时调度无公网端口
legacy-web旧版 UI 对照环境仅本机 8001；独立 job_tracker_legacy 数据库

7.3 Docker + Windows Host Agent

powershell -ExecutionPolicy Bypass -File "D:\New project\scripts\start-host-agent.ps1"
powershell -ExecutionPolicy Bypass -File "D:\New project\scripts\start-ollama.ps1"

Host Agent 启动后会向 Django 上报心跳，并领取 Outlook 同步或本地 Ollama 推理命令。代理离线时，已存业务数据和普通页面仍可用；仅 Outlook 同步与本地 AI 任务进入等待状态。

7.4 备份与恢复建议

  1. 定期导出 MySQL 业务数据库，并加密保存到项目目录外的受控备份位置。
  2. 备份 media/、.env、Host Agent 本地配置和 MySQL dump；不要把这些内容提交到 Git。
  3. 恢复时先恢复同版本代码与依赖，再恢复数据库，最后恢复媒体文件并执行 manage.py check。
  4. 不要把两台机器的 MySQL 数据目录直接双向复制；应保持一个可写主库，使用导出 / 导入或明确的同步流程。

9. 已知边界与演进方向

主题当前边界建议后续方向
邮件实时性当前依赖经典 Outlook + Host Agent；电脑休眠、Outlook 未登录或代理离线时无法即时同步。在服务器侧引入 Microsoft Graph OAuth、Webhook 与 Delta Query；Webhook 仅通知，增量同步负责恢复遗漏。
AI 本地运行本地 Ollama 受显存、模型能力和 Windows 进程状态影响；任务会等待 Host Agent。保留本地优先，并允许用户选择经授权的 OpenAI；为失败任务增加更清晰的重试与恢复界面。
多用户协作当前是个人用户空间模型，不包含团队、组织、共享岗位或审批角色。若扩展团队功能，应先引入 Workspace / Membership 边界，而非直接共享现有用户数据。
公网部署当前 Compose 使用 Django 开发服务器，适合本机开发与演示。生产采用 Gunicorn / Uvicorn、Nginx 或 Caddy、HTTPS、受限网络、备份与监控。
AI 自动化系统不自动批准候选、不自动投递、不自动回复邮件、不回写 Outlook。继续保持人工审核闸门；新增自动化前应先做权限、审计和撤销设计。
